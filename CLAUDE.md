# DatingRelating.com

Static site on GitHub Pages (custom domain via `CNAME`). No framework, no bundler. Pushing to `main` deploys in ~1 minute.

## Pages
- `/` Dating: tiles of possibly-single people, rendered client-side from `profiles.json` by `index.html` + `embeds.js`
- `/people/<id>/` personal pages, **generated** by `python3 build.py` for every profile with a `"bio"` (don't hand-edit; files carry a `generated by build.py` marker)
- `/relating/` Resentment Dismantlement Protocol, Mars Crew Pairing Protocol, Mars-144 (images first, text in "Read as text" toggles)
- `/frameworks/` credited frameworks (Dating Tech Spec by Olesya Kovalskaya; slides in `media/frameworks/<name>/NN.webp`)
- `/hacker-mindset/`, `/co-founder-co-lover/`, `/about/` (design choices + the ULTRA reflection)
- Shared: `style.css` (tokens, nav, panels, embed frames), `embeds.js` (embeds, dates, preloading)
- Every page has the same nav: Dating · Relating · Frameworks · Hacker Mindset · Co-founder & Co-lover · About. A new page needs the link added to all pages **and** to the template in `build.py`.

## Adding a profile (the most common task)
The owner sends a post link (Instagram, Threads or X) and usually a location. Add an entry to `profiles.json`:

```json
{
  "id": "username",                 // used in the share link /#id; lowercase, dashes ok
  "instagram": "username",          // or "threads" / "x"
  "post_url": "https://www.instagram.com/reel/CODE/",   // strip tracking query params
  "city": "London", "region": "", "country": "United Kingdom",
  "added": "YYYY-MM-DD"
}
```

Optional fields:
- `"hidden": true`: not in the public list; reachable only via `/#id`, shown first with an orange "Not publicly visible / Waiting for approval" notice
- `"pinned": true`: always first (the owner, `marsitatheultra`)
- `"relocation": true` shows "Relocation friendly"; `"passports": 3` shows "3× passport"
- `"age_restricted": true`: Instagram won't embed these; tile shows an 18+ "Open on Instagram" panel
- `"bio"`: enables a personal page and a "Read more →" link (blank line = new paragraph; URLs auto-link)
- `"note": "Explore the comments section"`: highlighted line above the embed, links to the post
- `"name"`, `"posted"` (override the date)

Notes:
- Post dates are decoded from the post ID (Instagram/Threads shortcode, X snowflake); no need to enter them.
- Threads `share/` links must be resolved to `threads.com/@user/post/CODE` (follow the redirect).
- If the username is unknown, use the post code as a temporary id and ask.
- Location order on tiles is broad to narrow: "United States, Utah, Salt Lake City"; empty = "Location unspecified".

## Homepage behaviour
- Order: `/#id` target first, then pinned, then a per-visitor stable random order (seed in localStorage).
- Embeds are iframes (no embed.js/widgets.js). First 6 load immediately, the rest ~3 screens ahead; heights come from postMessage.
- Each tile has a link icon (top right) that copies the `/#id` share link.

## Publishing
- Locally: `./publish.sh "message"` (runs `build.py`, commits everything, pushes).
- In a cloud session: run `python3 build.py`, then commit and push to `main`.
